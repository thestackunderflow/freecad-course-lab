`spawn uvx ENOENT` means Claude Desktop can't find `uvx` on its PATH. Desktop apps don't load your shell profile (`.bashrc`, `.zshrc`), so a `uvx` in `~/.local/bin` or `~/.cargo/bin` is visible in your terminal but not to Claude Desktop.

**Fix: use the absolute path to `uvx` as the `command`.**

1. Find the path in your terminal:
   ```bash
   which uvx        # Linux/macOS/WSL
   ```
   On Windows PowerShell, use `where.exe uvx`.

2. Edit `claude_desktop_config.json` (Settings → Developer → Edit Config):
   ```json
   {
     "mcpServers": {
       "freecad": {
         "command": "/home/maker/.local/bin/uvx",
         "args": ["freecad-mcp"]
       }
     }
   }
   ```
   Keep your existing `args` and use the path from step 1. The `/home/maker/.local/bin/uvx` above is just a typical location.

3. Fully quit Claude Desktop, including the tray icon, and reopen it.

**If you run Claude Desktop on Windows but `uvx` is installed in WSL**, as your environment suggests, a Linux path won't work from Windows. Either:
- Install `uv` on Windows (`winget install astral-sh.uv`) and use its `.exe` path, typically `C:\\Users\\<you>\\.local\\bin\\uvx.exe`. Remember to double the backslashes in JSON. This is the better option if FreeCAD itself runs on Windows.
- Or launch it through WSL:
  ```json
  "command": "wsl.exe",
  "args": ["-e", "/home/maker/.local/bin/uvx", "freecad-mcp"]
  ```
  This only works if FreeCAD is reachable from inside WSL.

Also check the FreeCAD side. The FreeCAD MCP addon (workbench) usually has to be installed in FreeCAD with its RPC server started. Otherwise the server will launch but fail to connect.
